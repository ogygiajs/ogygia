# @ogygia/flags

## 0.13.0

### Patch Changes

- [#256](https://github.com/ogygiajs/ogygia/pull/256) [`25ab8c7`](https://github.com/ogygiajs/ogygia/commit/25ab8c70c2d6faaab6a21294b66d0ef14421811f) Thanks [@PuruVJ](https://github.com/PuruVJ)! - An exposure sink that rejects no longer crashes the server: the failure is logged with a message code, and the sink's send is handed to the platform's `waitUntil` when it has one, so serverless instances no longer cut exposures off. The response never waits for the send ([#243](https://github.com/ogygiajs/ogygia/issues/243)).

- [#323](https://github.com/ogygiajs/ogygia/pull/323) [`7a53a56`](https://github.com/ogygiajs/ogygia/commit/7a53a56105714777cc3282552f52ddffc08e5414) Thanks [@PuruVJ](https://github.com/PuruVJ)! - Exposure batches go through an outbox: a batch the sink failed is tried again before the batch read after it, instead of being dropped, batches still reach the sink one at a time in order, and a send started by the size or age cap is kept alive past the response too ([#308](https://github.com/ogygiajs/ogygia/issues/308)).

- [#340](https://github.com/ogygiajs/ogygia/pull/340) [`24c6592`](https://github.com/ogygiajs/ogygia/commit/24c65929db2850cb4923309fce2a23316ff26b56) Thanks [@PuruVJ](https://github.com/PuruVJ)! - A flag source that throws before it awaits anything leaves the request resolved (every flag on its native rule), instead of priming for good ([#374](https://github.com/ogygiajs/ogygia/issues/374)).

- [#340](https://github.com/ogygiajs/ogygia/pull/340) [`24c6592`](https://github.com/ogygiajs/ogygia/commit/24c65929db2850cb4923309fce2a23316ff26b56) Thanks [@PuruVJ](https://github.com/PuruVJ)! - A second `prime_flags` of a request while the first still waits on the source now waits for that answer, instead of returning at once and leaving reads on the native rule ([#296](https://github.com/ogygiajs/ogygia/issues/296)).

- [#321](https://github.com/ogygiajs/ogygia/pull/321) [`17e009a`](https://github.com/ogygiajs/ogygia/commit/17e009ad985e6cda5ca371cd46e65f003c387471) Thanks [@PuruVJ](https://github.com/PuruVJ)! - A flag source that fails (a throwing source, an OFREP endpoint that errors or cannot be reached, an OpenFeature flag whose evaluation throws) now prints `flags_source_failed` once per failing streak, instead of falling back to the native rule without a word.

- [#175](https://github.com/ogygiajs/ogygia/pull/175) [`a99a49a`](https://github.com/ogygiajs/ogygia/commit/a99a49a724ecd61ee0e1388a4e659732a73f5939) Thanks [@PuruVJ](https://github.com/PuruVJ)! - Every ogygia error and warning has a code and a page at `ogygiajs.dev/e/<code>`: dev prints the wording and the link, a production build prints the link alone (`[ogygia] https://ogygiajs.dev/e/<code>?<args>`), so the wording stays out of the client and server bundles.

- [#184](https://github.com/ogygiajs/ogygia/pull/184) [`1767110`](https://github.com/ogygiajs/ogygia/commit/1767110f67734bfaffdd6243b3fb3406292746d4) Thanks [@PuruVJ](https://github.com/PuruVJ)! - Packages declare `sideEffects` (only their `.css` files run on import), so bundlers drop the modules an app never uses.
