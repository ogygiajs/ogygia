# @ogygia/devtools

## 0.13.0

### Minor Changes

- [#177](https://github.com/ogygiajs/ogygia/pull/177) [`d9e8e2f`](https://github.com/ogygiajs/ogygia/commit/d9e8e2f2b9bad0fa5d79a60d2b2001edc11985c6) Thanks [@PuruVJ](https://github.com/PuruVJ)! - The profiler's stores are classes: `new MemoryStore()`, `new SqliteStore()`, `new RedisStore()` and `new PostgresStore()` replace `memoryStore()`, `sqliteStore()`, `redisStore()` and `postgresStore()` (same arguments, same entry points).

### Patch Changes

- [#225](https://github.com/ogygiajs/ogygia/pull/225) [`29d8553`](https://github.com/ogygiajs/ogygia/commit/29d8553c9976d34cb39979f37eaedec84767e8b0) Thanks [@PuruVJ](https://github.com/PuruVJ)! - The profiler's visit beacons no longer take the first tab switch for the page leaving: coming back to the tab or a back/forward cache restore opens the visit again, so later navigations, interactions and shifts go out with the next hide, and the standalone beacon sends no copy after its final visit ([#209](https://github.com/ogygiajs/ogygia/issues/209)).

- [#187](https://github.com/ogygiajs/ogygia/pull/187) [`b46798f`](https://github.com/ogygiajs/ogygia/commit/b46798f90c26830c7f4eab0daf64602dee89edaa) Thanks [@PuruVJ](https://github.com/PuruVJ)! - Finding a load's constant work takes time in line with the load's lines: the functions it also calls elsewhere are read from one pass.

- [#255](https://github.com/ogygiajs/ogygia/pull/255) [`fc35032`](https://github.com/ogygiajs/ogygia/commit/fc35032b9ea0f6e47283c68cbac3ece369714441) Thanks [@PuruVJ](https://github.com/PuruVJ)! - Turning devtools off in a build now takes the whole dock with it: the app, its observers and its Alt+O listener go, a dock still downloading never mounts, and turning it on again runs one dock ([#239](https://github.com/ogygiajs/ogygia/issues/239)).

- [#215](https://github.com/ogygiajs/ogygia/pull/215) [`a7ce10d`](https://github.com/ogygiajs/ogygia/commit/a7ce10df35b3a79365dfff98687ed934215e8a36) Thanks [@PuruVJ](https://github.com/PuruVJ)! - The dock's button no longer sticks on "loading…" when its code fails to download: a click asks for it again ([#201](https://github.com/ogygiajs/ogygia/issues/201)).

- [#370](https://github.com/ogygiajs/ogygia/pull/370) [`9272db9`](https://github.com/ogygiajs/ogygia/commit/9272db994d85da6bbb68e0220f7087db4ad4e4a2) Thanks [@PuruVJ](https://github.com/PuruVJ)! - The devtools Page tab asks the dev server for a file's `Vary` header and for the pre-bundled packages again after a failed ask, instead of hiding those findings for the rest of the session ([#363](https://github.com/ogygiajs/ogygia/issues/363)).

- [#409](https://github.com/ogygiajs/ogygia/pull/409) [`44b3016`](https://github.com/ogygiajs/ogygia/commit/44b30165ff4471276502bf122e84872dfd0cd59c) Thanks [@PuruVJ](https://github.com/PuruVJ)! - The dock's save as a page goes (`pagehide`) no longer starts a request to the dev server, which WebKit reported as a page error.

- [#255](https://github.com/ogygiajs/ogygia/pull/255) [`fc35032`](https://github.com/ogygiajs/ogygia/commit/fc35032b9ea0f6e47283c68cbac3ece369714441) Thanks [@PuruVJ](https://github.com/PuruVJ)! - The dock's failed download is now logged as a message code with its page, `devtools_dock_load_failed`, like every other devtools message ([#239](https://github.com/ogygiajs/ogygia/issues/239)).
