# @ogygia/postrender

## 0.13.0

### Minor Changes

- [#177](https://github.com/ogygiajs/ogygia/pull/177) [`d9e8e2f`](https://github.com/ogygiajs/ogygia/commit/d9e8e2f2b9bad0fa5d79a60d2b2001edc11985c6) Thanks [@PuruVJ](https://github.com/PuruVJ)! - Postrender's stores and edges are classes: `new MemoryStore()`, `new ValkeyStore(client)`, `new UpstashStore({ url, token })`, `new CloudflareKvStore(binding)`, `new AkamaiEdge(cfg)`, `new CloudFrontEdge(cfg)` and `new CloudflareEdge(cfg)` replace `memoryStore()`, `valkey()`, `upstash()`, `cloudflareKv()`, `akamai()`, `cloudfront()` / `awsCloudfront()` and `cloudflare()` (same arguments).

### Patch Changes

- [#175](https://github.com/ogygiajs/ogygia/pull/175) [`a99a49a`](https://github.com/ogygiajs/ogygia/commit/a99a49a724ecd61ee0e1388a4e659732a73f5939) Thanks [@PuruVJ](https://github.com/PuruVJ)! - Every ogygia error and warning has a code and a page at `ogygiajs.dev/e/<code>`: dev prints the wording and the link, a production build prints the link alone (`[ogygia] https://ogygiajs.dev/e/<code>?<args>`), so the wording stays out of the client and server bundles.

- [#217](https://github.com/ogygiajs/ogygia/pull/217) [`739b763`](https://github.com/ogygiajs/ogygia/commit/739b76379ee1d31e895048c14c5bbed8852cfb12) Thanks [@PuruVJ](https://github.com/PuruVJ)! - A render that a publish (or any invalidation) lands during is served but not stored, so the page as it was before the publish is no longer kept ([#194](https://github.com/ogygiajs/ogygia/issues/194)).

- [#217](https://github.com/ogygiajs/ogygia/pull/217) [`739b763`](https://github.com/ogygiajs/ogygia/commit/739b76379ee1d31e895048c14c5bbed8852cfb12) Thanks [@PuruVJ](https://github.com/PuruVJ)! - A stampede flight settles however the request that opened it ends, so a plugin answering that request no longer leaves every later cold request for the page waiting ([#194](https://github.com/ogygiajs/ogygia/issues/194)).

- [#305](https://github.com/ogygiajs/ogygia/pull/305) [`e605070`](https://github.com/ogygiajs/ogygia/commit/e6050700637374f5e62d8601c0402ce98be2ffa4) Thanks [@PuruVJ](https://github.com/PuruVJ)! - Requests waiting on a page render that a publish overtook are let go at once and share one new render, which is stored, instead of waiting for the old render to end and then each rendering the page alone.

- [#217](https://github.com/ogygiajs/ogygia/pull/217) [`739b763`](https://github.com/ogygiajs/ogygia/commit/739b76379ee1d31e895048c14c5bbed8852cfb12) Thanks [@PuruVJ](https://github.com/PuruVJ)! - A response refused after its body was read is sent rebuilt from that body, not as the spent original.

- [#333](https://github.com/ogygiajs/ogygia/pull/333) [`865eb55`](https://github.com/ogygiajs/ogygia/commit/865eb5534698c803db04195941f05e094a37110b) Thanks [@PuruVJ](https://github.com/PuruVJ)! - A page whose render was stored just after a publish evicted it is no longer served while it is taken back out, and that evict is now tried again when the store fails it ([#332](https://github.com/ogygiajs/ogygia/issues/332)).

- [#321](https://github.com/ogygiajs/ogygia/pull/321) [`17e009a`](https://github.com/ogygiajs/ogygia/commit/17e009ad985e6cda5ca371cd46e65f003c387471) Thanks [@PuruVJ](https://github.com/PuruVJ)! - A store that is down now prints `postrender_store_failed` once per failing streak, instead of every render quietly missing and nothing being kept.

- [#370](https://github.com/ogygiajs/ogygia/pull/370) [`9272db9`](https://github.com/ogygiajs/ogygia/commit/9272db994d85da6bbb68e0220f7087db4ad4e4a2) Thanks [@PuruVJ](https://github.com/PuruVJ)! - A store outage is said once (`postrender_store_failed`) even while calls overlap: a slow store call that started before the outage and answers after it no longer ends the failing streak ([#364](https://github.com/ogygiajs/ogygia/issues/364)).

- [#323](https://github.com/ogygiajs/ogygia/pull/323) [`7a53a56`](https://github.com/ogygiajs/ogygia/commit/7a53a56105714777cc3282552f52ddffc08e5414) Thanks [@PuruVJ](https://github.com/PuruVJ)! - A successful form post's response now waits for its page's stored copy to be evicted (an outbox send, tried again within 2 s), so the redirect's GET right after renders fresh instead of getting the page from before the post ([#283](https://github.com/ogygiajs/ogygia/issues/283)).

- [#321](https://github.com/ogygiajs/ogygia/pull/321) [`17e009a`](https://github.com/ogygiajs/ogygia/commit/17e009ad985e6cda5ca371cd46e65f003c387471) Thanks [@PuruVJ](https://github.com/PuruVJ)! - A peer whose store fails to apply a thaw notice now answers an error, so the sender sends it again, instead of answering done and deduping the retry; `app.notify` rejects once every hook ran when one failed ([#287](https://github.com/ogygiajs/ogygia/issues/287)).
