'@ogygia/image': minor
---

New package `@ogygia/image`: list `image({ presets })` from `@ogygia/image/vite` beside `ogygia()`, read an image with `import.meta.og.image('./hero.jpg')` (or many with `import.meta.og.image.glob('./gallery/*.jpg')`), and render it with `<Img of={hero} preset="cover" alt="…" />`. The build reads each source once (its size and a blur placeholder of a few hundred bytes at most) and encodes nothing; `<Img>` picks the files from a preset or its own `layout` (`constrained`, `fullWidth`, `fixed`), `width`, `aspect` and `position`, and names each one by a signed URL that the image endpoint makes on first request, in dev and on a live server. A prerendered page's files (a `getImage()` CSS background too) are made by the build as static files under `_app/immutable/og/`, named by their recipe, so `adapter-static` sites need no server and keep the same image URLs across builds with no `OGYGIA_SECRET`. `import.meta.og.image(src, { warm: 'cover' })` makes a preset's files there at build for pages rendered on a live server. Crops are real files (a `1/1` thumbnail downloads a square), a fixed 48-pixel avatar asks for 48 and 96 only, animated GIFs become animated WebP, SVGs are served as they are, and a changed or unsigned URL is refused. `priority` preloads the page's main image from the head, `morph` names an image for a view transition, and the HTML carries no client script and no inline event handler (the placeholder and a crop are inline styles, the placeholder a `data:` image). sharp is a peer the app installs (`pnpm add @ogygia/image sharp`): a build or dev server that cannot find it in the app, or a server build that lists it only in `devDependencies` (adapter-node would bundle it, and every image would answer 500), fails with `image_sharp_missing`. The server loads sharp on the first image request, never at start; it keeps its files on disk to a size, answers from memory when the disk cannot write, sends a URL with a query string to the bare URL, and answers 503 past a bounded line of encodes. Every file is named by a hash of its source's bytes and is never made from an original that no longer matches it, so an edited image gets new URLs and an old page's URL answers 404, never the new pixels. A URL made absolute with `new URL(src, page.url)` (an `og:image`, an RSS feed) names the file at `kit.prerender.origin` on a prerendered page. `getImage()` gives the same answer outside the component, and `isImage` checks a frontmatter image field (`v.custom<ImageDescriptor>(isImage)`). A missing file, a file outside `src/`, a non-literal argument, an unknown option, an unknown preset, a descriptor whose id or placeholder the build did not make, a size of 0 or less (fractions are rounded) or an image too large to encode fails with a code.
